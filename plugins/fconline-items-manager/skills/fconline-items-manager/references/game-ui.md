# 게임 화면 조작

## 도구와 권한

Windows에서 실행 중인 제목 `FC ONLINE` 창을 찾는다. 여러 모니터, DPI 배율, 실제 client 크기를 먼저 확인한다. 전체 데스크톱의 고정 좌표를 복사하지 않는다. 기존 사진은 현재 화면의 근거가 아니다.

듀얼 모니터에서는 게임이 실제로 놓인 창을 캡처해 그 창 이미지 안의 좌표로 조작한다. 캡처 결과의 `client_size`는 실제 크기, `coordinate_width`는 입력 좌표 기준(1600)을 나타낸다. 전체 모니터/데스크톱 좌표, `full_image` 픽셀 좌표, 정규화된 캡처 좌표를 섞지 않는다. 매번 최신 캡처의 버튼 위치를 사용한다. 입력 전 `game_foreground`와 `elevated` 상태를 각각 확인하고, 하나만 보고 권한 문제라고 단정하지 않는다.

포함된 `scripts/game_ui.py`는 Python, Pillow와 Windows Win32 API를 사용한다. 네트워크·게임 메모리·패킷 조작은 하지 않는다. 기본 `capture`는 게임을 전경으로 가져오거나 입력하지 않는다. 스킬은 현재 사용자 프로필 아래 두고 읽기·실행에 관리자 권한이나 불필요한 ACL 확대를 요구하지 않는다. 기본 출력 위치는 `~/FCOnline/skill-ui-captures`이며 `--output-dir`로 바꿀 수 있다. 캡처는 게임 창 영역의 화면을 그대로 잘라내므로 그 위에 겹친 다른 창도 찍힐 수 있다.

`$uiScript`에는 이 스킬 폴더(SKILL.md가 있는 폴더, 호스트가 알려 주는 스킬 기준 디렉터리)의 `scripts\game_ui.py` 절대 경로를 넣는다. 캡처 이미지는 `--output-dir`(기본 `~/FCOnline/skill-ui-captures`)에 저장되며 닉네임·보유 재화 등 계정 정보가 보일 수 있으므로 저장 위치를 알리고 공유 전에 확인하도록 안내한다.

```powershell
$uiScript = "<스킬 폴더>\scripts\game_ui.py"
python $uiScript '{"action":"capture"}'
python $uiScript '{"action":"focus"}'
```

Windows PowerShell 5.1은 인자의 큰따옴표를 지워 `Expecting property name enclosed in double quotes` 오류가 난다. 그때는 JSON의 큰따옴표를 `\"`로 이스케이프한다(`python $uiScript '{\"action\":\"capture\"}'`). PowerShell 7.3 이상에서는 위 형태가 그대로 동작하므로 이스케이프하지 않는다.

각 호출은 JSON 상태와 **이번 호출에서 생성한** 이미지 경로를 반환한다. 성공 여부와 이미지 경로를 확인한 다음 호스트의 이미지 보기 도구(예: Codex `view_image`)로 열어 판단한다. 실패 후 예전 `game.png`를 보여 주며 새 작업이 성공했다고 해석하지 않는다.

좌표는 이미지 폭 1600 기준이다. 예를 들어 새 캡처에서 관찰한 위치를 `move`/`click`의 `x`,`y`에 넣는다. 아래 값은 호출 형식 예시이지 상품 위치가 아니다.

```powershell
python $uiScript '{"action":"move","x":800,"y":400,"wait":1.5}'
python $uiScript '{"action":"wheel","x":1300,"y":650,"amount":-120,"count":5}'
```

- 지원: `capture`, `focus`, `move`, `click`, `wheel`, `escape`, `number`.
- `click`은 게임 client 내부에서 mouse-down과 mouse-up 사이에 간격을 둔다. `wheel`은 현재 목록 위로 이동한 뒤 제한된 횟수만 스크롤한다.
- 이 스크립트의 `click`은 좌클릭이고 Space 키 입력도 지원하지 않는다. 우클릭 삭제나 Space 입력은 호스트가 제공하는 다른 입력 도구(예: Codex의 CUA)에서 현재 `FC ONLINE` 창을 목록으로 확인해 선택하고, 최신 창 화면을 캡처한 다음 수행한다. Codex `cua_repl`에서는 `app.click([x, y], { mouseButton: "right" })` 또는 `app.pressKey("space")`를 쓴다. 좌표는 해당 CUA 창 화면 기준이다. 다른 조작 도구를 쓸 때는 그 도구의 문서화된 호출 형식을 따르고 모니터 절대 좌표를 섞지 않는다.
- 숫자 입력은 화면에서 수량 입력칸을 확인하고 클릭한 뒤 `number`의 `value`에 6자리 이하 숫자를 지정한다. 입력칸이 직접 타이핑을 지원하지 않아 값이 유지되는 경우가 있으므로 표시된 최종 수량을 반드시 다시 읽는다.
- 입력은 게임이 전경일 때만 수행한다. `focus`는 전경 전환을 시도하고, 확인된 게임 제목 표시줄을 클릭할 수 있을 때만 보조적으로 사용한다. 전경 전환 실패와 `SendInput` 차단은 다른 오류다.
- 관리자 게임/일반 권한 도구 간 입력 제한이 확인되면 Windows 권한이 필요하다고 알린다. 스킬 저장·편집 권한 문제와 혼동하지 않는다.

## 정확한 수량 구매와 연속 개봉

- 구매 전 실제 품목명, 단가, 보유 재화, 구매 가능 수량을 화면에서 확인한다. 수량 선택 목록의 처음 보이는 `1~10`은 목록의 일부일 수 있다. 수량 숫자 자체를 눌러 목록을 연 뒤 목록 안에서 휠을 움직여 원하는 숫자를 선택한다. 화면에서 최대 99까지 선택 가능하면 요청·보유량에 맞는 정확한 수량을 고르고, 99를 넘을 때는 `99 + 나머지`처럼 나눠 매번 선택 수량과 총 비용을 확인한 후 구매한다. 10개씩 반복 구매하지 않는다.
- 구매 확인창에서 실제 구매 수량과 비용을 읽고, 성공 후 보관함의 품목명·수량을 대조한다. 결과가 모호하면 같은 구매를 다시 누르지 말고 현재 보유량과 구매 내역을 먼저 확인한다.
- 상자는 정확한 이름과 출처별로 보유량을 기록한다. 사용자가 특정 행사에서 받은 상자만 지목하면 새로 받은 수량과 기존 보유분을 구분하고, 지목된 수량만 연다. 개봉 재료가 부족해 잠긴 기존 상자는 남겨 둔다. 상자 화면에서 보유 개수, 잠금 해제 재료의 보유/필요량, 개봉 개수를 확인한다.
- 10개 개봉 후 연출 중 오른쪽 아래에 `SPACE` 키 상자와 `다음`이 나타나면 그 순간 바로 Space 키를 누른다. 키 입력 도구를 쓸 수 없으면 최신 캡처에서 그 표시 영역을 즉시 클릭한다. 이 표시는 잠시만 보일 수 있으므로 `wait: 1.5` 같은 긴 지연이나 다른 화면 작업을 끼우지 않는다. 프롬프트를 처리한 뒤 현재 결과를 확인하고, 개봉이 끝나기 전에 화면을 떠나지 말고 다음 묶음 버튼이 보이면 같은 상자 화면에서 반복한다.
- 남은 개수가 10보다 적으면 먼저 화면에 그 정확한 개수의 개봉 버튼이 있는지 확인하고 사용한다. 예를 들어 4개 남았을 때 `4개 개봉`이 있으면 4개를 한 번에 연다. 정확한 묶음 버튼이 없을 때만 1개씩 연다. 매 묶음 뒤 상자 수량, 잠금 재료 감소량, 획득 카드 수량을 확인한다.
- BP 카드 개봉 요청을 받으면 정확한 행사 카드 종류를 선택하고 선택 화면의 카드 수량/선택 한도를 확인한다. 묶음 한도가 있으면 예를 들어 150장씩 처리하되, 확인창의 총 선택 수량을 보고 확정한다. 로딩/진행률이 끝나면 결과 화면의 `총 획득 금액`을 확인하고 `완료`를 눌러 목록으로 돌아간다. 잔량을 새로 읽어 나머지 묶음을 이어서 연다. 이 카드 결과의 `완료`는 상자 애니메이션의 우하단 `SPACE 다음`과 다른 단계다. 이름이 비슷한 다른 카드나 요청 범위 밖의 기존 카드는 함께 선택하지 않는다.
- 상자 삭제를 요청받으면 먼저 해당 상자의 툴팁에서 해제 재료 아이템의 정확한 이름과 필요량을 읽고, 인벤토리에서 그 대응 재료의 실제 잔량을 확인한다. 재료가 남아 있으면 가능한 개봉분을 먼저 열고 다시 확인한다. 대응 재료가 0개일 때만 지목된 상자만 우클릭해 삭제 메뉴를 선택하고, 확인창의 품목명·수량을 대조한 뒤 삭제한다. 삭제 후 같은 필터/목록에서 해당 상자가 사라졌는지 확인한다. 다른 상자와 섞여 있거나 수량이 불명확하면 삭제하지 않는다.

## 화면에서 확인된 동작과 주의점

- 상점·아이템 창은 처음 열 때 아래에서 위로 이동하는 연출이 있다. 버튼 위치가 안정된 최신 캡처를 보고 다음 동작을 정한다. 전환 전 좌표를 연속으로 누르지 않는다.
- 아이템 목록은 처음엔 `모두 선택`이 비활성일 수 있다. 개봉 가능한 품목에 마우스를 올려 체크박스를 선택하면 종류별 일괄 선택 화면으로 바뀐다. 무엇이 선택됐는지 개수와 이름을 읽고 연다.
- 직접 `사용하기`로 고정 재화 카드 여러 장이 한꺼번에 사용된 사례가 있다. 한 장만 사용됐다고 추정해 반복 클릭하지 않는다.
- 랜덤 재화 카드는 `사용하기` → 개봉 화면 → `N개 열기` → 결과/0개 → 완료의 단계를 확인한다.
- 게임 상점 `스페셜 찬스`의 상품 목록 아래가 비어 보이더라도 화면에 있는 이벤트 배너가 진입 버튼일 수 있다. 실제 배너를 눌러 내부 이벤트 화면과 아래 추첨·누적 보상을 확인한다.
- 툴팁은 마우스 hover 후 기다려 확인한다. 표시되지 않으면 포커스·입력 성공·해당 상품 위치를 점검하고, 이름만 보고 사용처를 추정하지 않는다.
- 게임에는 모달·결과 화면·상위 상점·에이전트 화면이 겹칠 수 있다. 닫기를 누르면 어느 층으로 돌아왔는지 새 화면을 읽는다.
- 의뢰 반복 투입은 `추가` 버튼으로 한 회분씩 누적할 수 있다. 투입 카드 총량, 표시된 반복 횟수, 결과 보상 수량을 맞춘 뒤 최종 의뢰를 진행한다.

독립된 사용 시도 에이전트를 사용하도록 요청받았을 때만 그 작업을 분리한다. 같은 게임 창을 두 에이전트가 동시에 조작하지 않는다.
