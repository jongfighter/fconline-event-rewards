# FC 온라인 아이템 정리·감독모드

## 작업 범위와 화면

- 아이템 소진·BP화는 실행 중인 `FC ONLINE` 게임 클라이언트에서 처리한다. 웹 이벤트 페이지를 대신 조작하지 않는다. 현재 게임 창과 모니터를 찾아 최신 화면부터 확인한다.
- 요청 범위를 이어서 유지한다. `박스·카드 다 열어`, `다른 상품도 소비처 찾아 소진`, `끝나면 감독모드`는 현재 작업에 추가된 지시다. 수령만 요청했다면 교환·소비까지 자동으로 확대하지 않는다.
- 직접 입력이 필요할 때 [게임 조작 참고](references/game-ui.md)를 읽는다. 포함된 `scripts/game_ui.py`는 화면 캡처와 제한된 Win32 입력용이며, 스킬을 읽거나 수정하는 데 관리자 권한이 필요하지 않다.
- 입력이 막히면 프로세스 권한과 전경 창 상태를 구분한다. 관리자 게임에 입력할 권한이 부족하면 그 사실과 필요한 Windows 승인을 명확히 설명한다. 승인 요청이 허용되지 않는 환경에서는 사용자에게 필요한 수동 조치를 알린다. 자동 권한 상승·보호 기능 우회·상주 관리자 서비스는 만들지 않는다.

## 수령 → 박스 → 카드 → 교환 → 재수령

1. **보관함을 먼저 비운다.** `모두 받기`와 확인을 누른 뒤 보관함 잔량을 확인한다. 선물·구매 미정 상품 등 개별 수령 예외도 실제 화면에서 확인한다.
2. **박스 개봉을 요청받았을 때만 연다.** 사용자가 박스 개봉이나 전체 개봉을 명시한 경우 개봉 가능한 대상 상자를 열고 결과 화면을 확인한다. 사용자가 행사나 획득분을 특정하면 그 이름·출처·수량만 대상으로 삼고, 기존 보유분이나 다른 행사의 상자는 섞어 열지 않는다. 박스에서 또 박스나 선수팩·재화 카드가 나오므로 목록을 새로 확인한다. 선택형은 현재 구성과 사용자 목적에 따라 고르고, 열쇠형은 현재 보유/필요 수량을 확인한다. 개봉 요청이 없으면 상자를 열지 말고 수량과 조건을 보고한다.
3. **카드·선수팩 개봉도 요청받았을 때만 한다.** 사용자가 카드 개봉이나 전체 개봉을 명시한 경우 종류별 일괄 선택 또는 사용을 활용한다. 고정 TC·SC·CP 카드는 즉시 일괄 처리될 수 있고, 랜덤 재화 카드는 별도 `N개 열기` 단계가 있다. 개봉 연출 진입을 완료로 간주하지 말고 결과·잔량까지 확인한다. 카드 개봉 요청이 없으면 상자 결과에 포함된 카드를 열지 않고 남은 수량을 보고한다.
4. **교환용 카드의 소비처를 조사한다.** 아이템마다 마우스를 올려 툴팁에서 정확한 이름, 보유량, 사용 기한, 상점/에이전트 경로, 추가 재료를 기록한다. 가능한 소비처를 재료가 충분한 경로와 조건이 필요한 경로로 나누어 실행한다.
5. **목적에 맞게 소진한다.** BP화를 요청했다면 가능한 BP 보상을 우선하고, BP화가 어렵다면 카드·다른 상품으로 받는다는 사용자의 선호를 적용한다. 상점의 소액 교환과 에이전트 반복 투입으로 잔량을 줄인다. 남은 수량을 줄이기 위해 무의미한 변환을 순환시키지 않는다.
6. **새 보상을 다시 확인한다.** 상점·추첨·에이전트 보상은 보관함으로 갈 수 있으므로 새 보상과 추가 재료를 식별하고 종류·수량·조건을 재점검한다. 새 상자·카드는 사용자가 해당 작업의 개봉을 요청한 범위에 포함될 때만 연다. 개봉 요청이 없으면 보관하고 남은 수량을 보고한다. 접속 보상이 계속 들어와도 무한 대기하지 말고 완료 시점의 수령분을 기준으로 마감한다.

## 소진 판단

- `모두 소진`을 보유 선수 매각·강화·주전 투입·코치 삭제·유료 구매까지 자동 허가한 것으로 해석하지 않는다. 그런 행동이 따로 요청되었다면 그 범위에서 진행한다. 강화 보호권은 실제 강화가 필요하고 수수료 쿠폰은 판매대금 수령이 필요하므로 단순 재화 카드와 구분한다.
- 기존 재료만으로 가능한 교환은 사용자의 소진 지시 안에서 실행한다. 재료 부족을 메우려고 임의로 FC·현금·BP를 지출하거나 선수를 희생하지 않는다.
- 품목명·수량·가격은 매번 현재 화면으로 확인한다. 과거 날짜의 가격이나 잔량을 현재 값으로 사용하지 않는다. 예전 사례와 추가 확인법은 [소비처 참고](references/item-routes.md)를 읽는다.
- `의뢰를 못 찾음`, `대상 선수가 안 보임`만으로 사용 기간 종료를 확정하지 않는다. 의뢰 필터·탭·스크롤 범위를 점검하고 정확히 같은 아이템에 대한 공식 공지의 기간과 대조한다. 종료일을 확인하지 못하면 확인한 범위와 미확정 사유를 구분해 보고한다.
- 만료 품목도 자동 삭제하지 않는다. 사용자가 특정 상자 삭제를 지시하면 먼저 툴팁에서 해제 재료와 필요량을 확인하고, 대응 재료 아이템이 남아 있으면 열 수 있는 수량을 먼저 개봉한다. 대응 재료가 0개인지 확인한 뒤에만 사용자가 지목한 정확한 상자·수량을 삭제한다. 삭제 확인창과 이후 목록에서 제거됐는지 확인한다. 삭제 입력이 실패하면 삭제 완료로 보고하지 않는다.
- 한 단계가 멈췄으면 최신 화면을 먼저 보고 결과를 확인한다. 이미 지급됐을 수 있는 구매·추첨·의뢰를 무작정 다시 누르지 않는다. 같은 실패가 재현되면 원인에 맞는 다른 확인 경로를 사용하고, 진행할 수 없는 품목을 기록한 뒤 다른 품목으로 넘어간다.

## 요청된 감독모드 시작

- 아이템 정리가 끝난 뒤 `공식경기 감독모드 → 공식경기`로 들어가 현재 선택 스쿼드·전술을 확인한다. 별도 변경 요청이 없으면 기존 설정으로 시작한다.
- 계속 돌려 달라는 요청은 가능한 `연속 진행` 횟수로 시작한다. 버튼의 실제 횟수를 읽고, 매칭 후 실제 경기 진입까지 확인한다. 매칭 대기만 확인했다면 그 상태로 보고한다.
- 이미 경기 중이면 중도 포기하지 않고 경기 경계에서 필요한 작업을 수행한다. 별도 확인 작업으로 연속 진행을 멈췄다면 현재 요청에 맞게 복구한다. 과거에 요청했던 컴퓨터 종료·코치 정리는 새 요청 없이 반복하지 않는다.

## 완료 보고

수령 여부, 실제 사용한 재료 수량, 개봉 결과, 남은 품목의 조건, 감독모드 상태를 간단히 보고한다. `모든 아이템 소진`과 `개봉·교환 가능한 항목 처리 완료`를 구분한다. 필요하면 사용자가 지정한 작업 폴더에 날짜별 처리 기록과 근거 캡처를 남기고 링크한다. 캡처에는 닉네임·보유 재화 등 계정 정보가 보일 수 있으므로 저장 위치를 알리고 공유 전에 확인하도록 안내한다.
