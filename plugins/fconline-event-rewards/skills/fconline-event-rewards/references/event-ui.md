# 웹 보상 탐색 참고

## 공식 진입 경로

- 초기 페이지는 `https://events.fconline.nexon.com`이다. 여기서 현재 이벤트 목록과 GNB의 `시즌 이벤트`·`장기 이벤트`를 확인한 뒤 각 이벤트로 이동한다.
- 이벤트 목록, 공식 웹상점, 플레이어스 멤버십, 구매 멤버십을 구분한다. 멤버십은 현재·지난달 등급 보상, 유지/페이백 조건이 다를 수 있다.
- 계정별 진행 현황을 확인한 뒤 접속·플레이·스페셜·PC방·콜라보·포인트 적립 등 현재 가능한 보상을 판단한다.

## 매번 확인할 이벤트

사용자가 FC 온라인 보상 수령을 요청하면 공식 진입 페이지 `https://events.fconline.nexon.com`에서 현재 이벤트 목록을 확인한다. GNB의 `시즌 이벤트`와 `장기 이벤트` 목록에 있는 이벤트 페이지를 모두 연다. 이벤트 URL을 고정 목록으로 가정하지 않는다.

- 수령 기간 중인 이벤트는 모두 확인한다. 목록에 없는 과거 이벤트 URL은 직접 열지 않는다.
- 페이지가 종료·이동·오류 상태면 현재 목록에서 새 주소나 후속 안내를 찾고, 찾지 못한 페이지는 결과에 남긴다.
- 목록에 있는 항목을 빠짐없이 대조한다. 2026-10-19에 콜라보 이벤트 페이지를 누락한 사례가 있다.

## 퀴즈와 방문 미션

- 퀴즈 문제와 모든 보기를 정확히 읽고, 먼저 해당 이벤트의 공식 안내·공지·게임 가이드에서 답 근거를 찾는다. 공식 자료만으로 답이 분명하지 않으면 문제의 핵심 문구를 웹 검색하고 신뢰할 수 있는 공개 자료로 교차 확인한다. 문제를 검색하거나 답을 찾기 어렵다는 이유만으로 미션을 건너뛰지 않는다.
- 근거가 있는 답을 선택한 뒤 정답·참여 완료 메시지 또는 상태 변화를 확인하고 참여 현황을 다시 조회한다. 합리적인 조사 후에도 답이 불확실하면 임의로 찍지 말고 미완료 사유를 남기며 다른 이벤트를 계속한다.
- `방문하기`는 현재 버튼의 목적지를 화면과 DOM에서 확인하고 실제로 연다. 페이지가 로드된 뒤 이벤트로 돌아와 참여 현황을 갱신하고 방문 미션 완료를 확인한다. 링크 클릭이나 새 탭 생성만으로 방문 완료를 보고하지 않는다.
- 방문 목적지에서 보상 미션과 무관한 가입, 게시, 결제, 다운로드, 권한 부여 같은 별도 행위를 요구하면 진행하지 않고 요구된 조치와 미완료 상태를 보고한다.

## 확인된 함정

- **콜라보 원투패스:** 현황 조회가 빈 접근성 이름의 이미지형 버튼이었다. 과거 selector는 `button[data-clickbtn="btn_Refresh_status"]`. 현재 DOM/화면에서 다시 확인하고 누른 뒤 비활성 보상을 판단한다.
- **신규/복귀:** 처음 서버 응답이 실패했다고 계정이 대상이 아니라고 말하지 않는다. 조회가 정상 완료된 뒤 대상 여부를 구분한다.
- **PC방·주차 보상:** 현재 주차만 보지 말고 수령 기간이 남아 있는 지난주 탭도 확인한다. 표시된 코인은 수령 가능 수와 보유 수가 다를 수 있다.
- **이전 달·투표:** 투표한 시점과 보상 개시일이 다를 수 있다. 현재 보상 수령 기간과 수령 완료 기록을 확인한다.
- **이벤트 자원과 게임 아이템:** 페이지 내 코인/참여권과 게임 보관함으로 지급되는 카드·상자는 별개다. 같은 이름처럼 보이더라도 실제 지급 위치를 확인한다.
- **모달·alert:** 수령 후 완료 메시지와 버튼 상태를 기록하고 모달이 닫힌 것을 확인한 뒤 다음 버튼을 누른다. 이미 처리됐을 수 있는 요청은 상태 확인 없이 중복 실행하지 않는다.
- **일부 UI 누락:** 로그인 상태, 갱신·새로고침, 현재 공식 목록을 통한 재진입을 점검한다. 여러 경로에서 같은 부분이 없다면 확인한 한계로 기록하고 다른 이벤트를 계속한다.

## Playwright MCP 실행 레시피 (실제 실행으로 확인)

- **별도 `조회`가 없는 페이지:** 통합 이벤트처럼 로드 시 현황(접속·플레이 진행도, 수령 상태)이 자동으로 채워지는 페이지가 있다. `조회`가 안 보인다고 갱신을 누락한 것으로 보지 말고, 진행도 값이 채워졌는지 확인한다. `조회`가 있는 페이지는 `[data-clickbtn="btn_view"]`·`btn_Refresh_status`처럼 이름이 비어 있는 이미지형 버튼일 수 있으니 DOM의 `data-clickbtn`으로 찾는다.
- **텍스트 없는 상태 버튼:** 수령 상태가 이미지로만 표시되면 클래스로 읽는다. 관찰된 예: 보상 카드의 `isClaimedHidden`(수령됨), `btnGet done`(수령 완료)·`btnVote end`(투표 종료), 월 탭의 `disable`(아직 열리지 않음). 클래스만으로 확신할 수 없으면 해당 영역을 스크린샷으로 직접 확인하고, 불확실하면 클릭하지 않는다.
- **공백 없는 텍스트:** 버튼 텍스트와 접근성 이름은 요소 사이에 공백이 없을 수 있다(`로그인최근 로그인`, `월4/9`). 정규식은 공백 위치에 의존하지 말고 `\s*`로 쓴다. 로케이터는 일치 개수를 먼저 세고 정확히 1일 때만 누른다.
- **선택자:** `[data-clickbtn="…"]`, 역할·이름 로케이터(`role=button[name=/…/]`), 클래스를 쓴다. `[type="submit"]`은 속성이 없는 기본 submit 버튼에 맞지 않는다. `:has-text` 같은 확장 문법은 도구 버전에 따라 거부될 수 있다. `role=…` 선택자는 둘 이상 일치하면 strict mode 오류로 실패하므로 별도 개수 확인 없이도 정확히 1개가 보장된다.
- **탭형 메뉴:** GNB의 `시즌 이벤트`·`장기 이벤트`·`웹상점`은 눌러야 해당 탭의 링크가 DOM에 나타나고 이전 탭의 링크는 사라질 수 있다. 탭마다 눌러 목록을 따로 수집해 합친다.
- **alert·모달:** 도구의 대화상자 처리나 `page.on('dialog')`로 문구를 기록한 뒤 닫는다. 모달은 `getByRole('button', { name: '닫기' })` 같은 역할 기반으로 닫고, 실패를 `.catch`로 삼키지 말고 실제로 닫혔는지 확인한다.
- **스냅샷 파일:** 이동·클릭 뒤 응답에 링크되는 `.playwright-mcp/page-*.yml`은 호출하지 않아도 자동 저장된다. 로그인 폼이 열린 동안 생긴 파일은 열지 않는다.

## 마일리지 추가 구매가 명시된 경우

현재 마일리지 잔액, 만료 예정분, 상품 단가·한도와 지급 내용을 읽는다. 사용자의 목적에 맞춰 기존 마일리지 안에서 구매하고 최종 잔액·완료 상태를 확인한다. FC·현금 충전이나 다른 재화로의 확장은 별도 지시가 있을 때만 한다. 과거 구매 조합·잔액을 오늘 값으로 쓰지 않는다.

## 계정 기록과 재사용

- 이벤트 페이지의 현재 조회 결과를 기준으로 처리한다. 과거 상태 기록이 제공되더라도 현재 날짜·주차·조건·수령 여부를 다시 조회한다.
- 계정별 이벤트 기록, 브라우저 상태 파일, 로그인 정보는 공개 스킬 파일에 복사하지 않는다.
