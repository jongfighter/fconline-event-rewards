# FC 온라인 웹 이벤트 보상

## 범위와 접속

- 호스트에서 사용할 수 있는 로그인된 브라우저와 웹 검색 도구로 공식 사이트를 확인한다. 로그인이 필요하면 넥슨 공식 로그인 화면인지 확인한다. 사용자가 로그인까지 맡겼다면 넥슨 ID 로그인 폼의 필수 입력란이 이미 채워져 있고 추가 인증 단계가 없을 때 화면의 `넥슨 ID 로그인` 버튼을 눌러 제출한다. 로그인 성공은 계정별 페이지 상태로 확인하고 같은 세션에서 미완료 단계를 이어간다. 로그인 정보는 입력 여부만 확인하며 값 자체를 캡처·복사·출력·기록하거나 사용자에게 노출하지 않는다. 입력란이 비어 있거나 CAPTCHA·2단계 인증·QR 로그인 등 추가 절차가 필요한 경우 해당 인증만 사용자에게 요청한다. 사용자가 로그인까지 맡기지 않았다면 해당 브라우저에서 직접 로그인하도록 요청한다. 공개 이벤트 조사처럼 인증이 필요 없는 일은 계속한다. 스킬 패키지는 브라우저, 검색 도구, 넥슨 인증을 설치하거나 제공하지 않는다. 필요한 도구를 쓸 수 없으면 막힌 단계를 밝히고 독립적으로 진행 가능한 확인은 계속한다.
- 보상 요청에는 보상 버튼뿐 아니라 보상을 열기 위해 필요한 참여 미션도 포함된다. 퀴즈·방문·출석 등 현재 수행 가능한 미션은 완료하고 보상 지급 조건을 다시 확인한다.
- 매번 [이벤트 경로와 UI 참고](references/event-ui.md)를 읽고, 필수 이벤트 전체와 이벤트 GNB의 `시즌 이벤트` 목록을 확인한다. 과거 기록은 조사 경로만 참고하며 현재 날짜·조건·수령 상태는 다시 조회한다.
- 웹 이벤트의 포인트·쿠폰·보상 수령과 게임 아이템 보관함 처리는 별개다. 아이템 개봉·쏠돌코인 소비는 `fconline-items-manager`로 연결한다.

## 이벤트 코인형 미니게임

- 참참참·승부차기처럼 이벤트 안의 미니게임을 완료해야 보상이 확정되는 경우도 보상 수령 작업에 포함한다. 현황을 조회한 뒤 보유 코인, 회차별 비용, 보상 단계와 확률, 마지막 시도의 효과, 초기화 조건, 코인 만료 시점을 최신 공식 안내에서 확인한다.
- 사용자가 이벤트 보상을 받아 달라고 하거나 미니게임을 진행하라고 하면, 이미 획득한 무료 이벤트 코인으로 진행 가능한 시도까지 마친다. 결과가 무작위라는 이유만으로 무료 이벤트 시도를 남겨두지 않는다. 선택 가능한 보상이나 방식이 있으면 공식 확률·보상표와 최신 공개 시세를 찾아 기대 가치와 보장 하한을 비교한다. 정확한 확률·시세를 확인하지 못하면 그 한계를 알리고 하한이 높고 변동성이 낮은 보상을 우선한다. 결과가 자동으로 무작위 결정되고 선택지가 없는 미니게임이면 결과를 바꾸려는 조작을 하지 말고 이벤트 버튼으로 진행한다.
- 코인을 쓰기 전에 마지막 시도로 회차가 끝나는지, 완료하면 잔여 코인이 사라지는지, 초기화가 이미 쓴 코인과 진행을 없애는지 확인한다. 사용자가 이벤트 보상 수령이나 미니게임 진행을 요청했다면 보상을 확정하는 마지막 시도까지 실행하고, 지급 완료 메시지 또는 완료 상태를 확인한다. 이미 진행한 회차를 임의로 초기화하지 않는다.
- 현재 보유한 무료 이벤트 코인만으로 완주할 수 없다면 그 코인으로 가능한 단계까지 진행하고 멈춘다. 공식경기(친선 제외 1vs1·2vs2)처럼 별도 게임 경기가 필요해도 직접 시작하거나 대신 플레이하지 않는다. 공식 안내로 모드·코인 획득 조건과 필요한 경기 수를 확인해 사용자가 해야 할 일을 안내한다. 슛마다 필요한 경기 수가 다르면 남은 슛별 코인 비용과 총 경기 분량을 계산한다. 사용자가 경기를 마친 뒤 돌아오면 `조회`로 참여 현황을 갱신하고 저장된 단계부터 이어간다. 코인을 사거나 FC·BP·넥슨캐시·게임 보관함 아이템·다른 재화를 대신 사용하지 않는다.
- 예: 8회 승부차기의 4·7번째 슛은 2코인씩 필요하고 현재 6코인뿐이라면 앞선 단계의 비용을 계산해 가능한 시도를 진행한 다음, 남은 슛과 재개에 필요한 코인을 정확히 보고한다. 8번째 슛이 즉시 회차를 끝내는 규칙이면 누르기 전에 그 규칙과 보상표를 다시 확인한다.

## 이벤트마다 조회 → 미션 → 수령 → 검증

1. **참여 현황을 먼저 새로고침한다.** `조회`, `조회하기`, 참여 현황 갱신을 누르고 비동기 로딩·알림·모달이 끝날 때까지 기다린다. 초기 비활성 보상 버튼만으로 조건 미달을 판단하지 않는다.
2. **화면과 DOM을 함께 읽는다.** 조회 버튼이나 미션이 이미지형이거나 접근성 이름이 비어 있으면 최신 화면과 DOM에서 실제 요소를 식별한다. 과거 selector는 현재 페이지에서 요소와 목적을 확인한 뒤 사용한다.
3. **잠금 조건을 채운다.** 퀴즈라면 질문과 모든 보기를 확보한 뒤 공식 이벤트 안내·공지·가이드부터 검색하고, 필요한 경우 공개 웹 자료로 사실을 교차 확인해 가장 근거 있는 답을 선택한다. 정답·참여 완료 메시지나 상태 변화를 확인한 뒤 현황을 다시 조회한다. `방문하기`는 버튼의 공식 목적지에 실제로 이동해 페이지가 열린 것을 확인하고, 이벤트로 돌아와 현황을 갱신해 방문 기록을 확인한다. 버튼을 누른 것만으로 미션 완료라 하지 않는다. 불확실한 퀴즈는 추측하지 말고 그 항목만 미완료로 남긴 뒤 다른 미션과 이벤트를 계속한다.
4. **조건이 충족된 보상을 수령한다.** 날짜·주차·월 탭, 지난 기간 중 수령 가능한 보상, 화면 아래 추가 보상도 확인한다. 조회가 정상 완료된 후 신규/복귀 대상 여부를 판단한다.
5. **지급을 확인한다.** 지급 완료 메시지 또는 수령 완료 상태를 읽는다. 클릭 성공만으로 수령을 보고하지 않는다. 결과가 불명확하면 최신 상태를 다시 읽고, 이미 수령됐을 가능성이 있으면 중복 클릭하지 않는다.
6. 이벤트별 결과를 `새로 수령`, `이미 수령`, `조건 미달/미션 미완료`, `기간 종료`, `조회 미확정/로그인 필요` 중 하나로 기록한다. 한 페이지의 오류를 반복 시도하지 말고 다른 페이지를 계속 확인한다.

## 웹상점·멤버십과 추가 구매

- 요청에 맞는 현재 웹상점의 플레이어스/구매 멤버십 및 현재·지난달/지난주 보상을 확인한다. 등급, 기간, 보유/수령 상태를 새로 확인한다.
- `보상 수령`만 요청했다면 포인트·마일리지·코인 교환이나 상품 구매를 하지 않는다. 사용자가 구매를 별도로 요청하면 잔액·단가·한도·기한을 확인하고 해당 요청 범위에서만 진행한다. FC·넥슨캐시 충전이나 다른 재화 소진은 별도 지시 없이는 하지 않는다.
- 웹 수령만으로 게임 보관함 지급·개봉까지 완료했다고 말하지 않는다. 지급 지연 안내가 있으면 그 지연을 보고하고, 게임 아이템 처리를 요청받은 경우 해당 스킬로 이어간다.

## 완료 보고

새로 수령한 핵심 보상, 이미 수령된 항목, 미완료 미션과 원인, 지급 지연 또는 UI 오류를 간단히 구분해 보고한다. **사용자 후속 행동**을 반드시 포함한다. 별도 경기가 필요하면 진행 현황, 필요한 공식 모드, 남은 경기 수와 코인 비용, 사용자가 경기 후 이벤트에서 `조회`하고 다시 이어갈 절차를 적는다. 추가 행동이 없으면 `없음`으로 적는다. 별도 기록은 사용자가 지정한 위치에 요청된 경우에만 남긴다.
