# FC 온라인 웹 이벤트 보상

## 범위와 접속

- 호스트에서 사용할 수 있는 로그인된 브라우저와 웹 검색 도구로 공식 사이트를 확인한다. 로그인이 필요하면 아래 `로그인과 계정 입력` 절차를 따른다. 공개 이벤트 조사처럼 인증이 필요 없는 일은 계속한다. 스킬 패키지는 브라우저, 검색 도구, 넥슨 인증을 설치하거나 제공하지 않는다. 필요한 도구를 쓸 수 없으면 막힌 단계를 밝히고 독립적으로 진행 가능한 확인은 계속한다.
- 보상 요청에는 보상 버튼뿐 아니라 보상을 열기 위해 필요한 참여 미션도 포함된다. 퀴즈·방문·출석 등 현재 수행 가능한 미션은 완료하고 보상 지급 조건을 다시 확인한다.
- 매번 [이벤트 경로와 UI 참고](references/event-ui.md)를 읽고, 공식 진입 페이지의 현재 이벤트 목록 전체와 GNB의 `시즌 이벤트`·`장기 이벤트` 목록을 확인한다. 과거 기록은 조사 경로만 참고하며 현재 날짜·조건·수령 상태는 다시 조회한다.
- 웹 이벤트의 포인트·쿠폰·보상 수령과 게임 아이템 보관함 처리는 별개다. 아이템 개봉·쏠돌코인 소비는 사용자가 요청한 경우에만 다룬다. 이때 `fconline-items-manager` 스킬을 쓸 수 있으면(플러그인이든 직접 설치한 스킬이든) 그 스킬로 연결하고, 없으면 사용자가 게임에서 직접 처리하도록 안내한다.

## 로그인과 계정 입력

보상 수령 요청에는 로그인 진행이 포함된다.

1. 계정별 페이지 상태로 로그인 여부를 먼저 확인한다. 이미 로그인되어 있으면 로그인 절차를 건너뛴다.
2. 로그인 상태가 아니면 공식 이벤트 페이지의 로그인 버튼을 직접 찾아 누른다. 열린 화면의 주소는 도구 응답의 `Page URL` 줄이나 `location.hostname` 평가로 확인하고, `hostname === 'nexon.com'` 또는 `hostname.endsWith('.nexon.com')`일 때만 진행한다(부분 문자열 일치로 판단하지 않는다). 아니면 입력을 요구하지 말고 멈춘 뒤 사용자에게 알린다.
3. 넥슨 ID 로그인 폼에서 아이디 입력란과 비밀번호 입력란이 각각 채워져 있는지만 확인한다. 브라우저 도구의 페이지 스냅샷·스크린샷·폼 읽기·텍스트 찾기(`browser_find` 등)·네트워크 요청 본문 조회는 비밀번호 칸을 포함한 입력값을 그대로 돌려줄 수 있으므로, 로그인 폼이 열려 있는 동안(사용자가 입력을 마친 뒤 제출하기 전까지 특히)에는 호출하지 않는다. 대신 값 길이가 0보다 큰지 참·거짓으로만 반환하는 스크립트 평가를 쓴다(예: `() => [...document.querySelectorAll('input:not([type=hidden]):not([type=checkbox]):not([type=radio]):not([type=submit]):not([type=button])')].map(i => ({ id: i.id, name: i.name, type: i.type, filled: i.value.length > 0, visible: i.offsetParent !== null }))`는 입력란마다 `id`·`name`·유형·채움 여부·화면 표시 여부만 돌려주므로 어느 칸이 비었는지 알 수 있고 숨은 입력란은 `visible: false`로 구분된다). 값 자체를 반환하는 평가는 쓰지 않는다. 입력란(`input`, `role=textbox` 등)을 대상으로 한 클릭·입력 선택자도 쓰지 않는다(strict mode·타임아웃 같은 실패 메시지가 일치한 요소의 마크업과 `value` 속성을 그대로 되돌릴 수 있다). 그 밖에 입력값을 돌려줄 수 있는 모든 도구(콘솔·네트워크 로그, 값을 반환하는 코드 실행 포함)도 로그인 폼이 열려 있는 동안 쓰지 않는다. 도구가 자동으로 돌려준 화면 정보에 값이 보이더라도 응답·기록·캡처에 옮기지 않는다. 결과는 `채워짐`/`비어 있음`으로만 다룬다. 값 길이로 판단할 수 없으면(자동 채움이 사용자 조작 전까지 값을 노출하지 않는 경우 등) 사용자에게 입력란이 채워져 있는지 묻는다.
   - Playwright MCP는 이동·클릭 뒤에 응답이 링크하는 스냅샷 파일(`.playwright-mcp/page-*.yml`)을 호출하지 않아도 자동으로 저장한다(위치는 응답이 링크하는 경로를 따른다). 그 파일을 열지 않는다(9단계의 개수 확인만 예외다).
4. **아이디나 비밀번호 중 하나라도 비어 있으면 사용자에게 직접 입력을 요구하고 멈춘다.**
   - 대신 입력하거나 추측하지 않는다. 파일·메모리·이전 대화·브라우저 저장 정보에서 계정 정보를 찾아 채우지 않고, 브라우저나 비밀번호 관리자의 자동 채움 항목을 대신 선택하지도 않는다. 채팅으로 아이디·비밀번호를 보내 달라고 요청하지 않는다.
   - 열려 있는 브라우저의 넥슨 로그인 화면에 사용자가 **본인이 직접** 입력하도록 요청한다. 사용자가 자동 채움 항목을 직접 고르는 것은 직접 입력으로 본다. 어느 입력란(아이디·비밀번호)이 비어 있는지만 알리고, 값은 채팅에 쓰지 말고 브라우저에만 입력하도록 안내한다.
   - 사용자가 입력을 마쳤다고 알릴 때까지 기다린다. 기다리는 동안 인증이 필요 없는 공개 조사는 먼저 해도 된다. 알리면 입력란을 다시 확인하고 둘 다 채워졌을 때만 다음 단계로 간다. 여전히 비어 있으면 다시 요청한다.
5. 둘 다 채워져 있고 추가 인증 단계가 없으면(CAPTCHA·보안문자·2단계 안내가 없는지 `document.body.innerText`로 확인) 화면의 `넥슨 ID 로그인` 버튼을 눌러 제출한다. 스냅샷 없이 접근성 이름 기반 로케이터로 누르고, 일치 개수가 정확히 1일 때만 누른다. 접근성 이름은 공백 없이 이어질 수 있으므로(실제 이름이 `넥슨 ID 로그인최근 로그인`이었다) 이름 정규식은 `/넥슨 ID 로그인/`처럼 공백 위치에 의존하지 않게 쓴다. `[type="submit"]` 속성 선택자는 속성 없이 기본값만 submit인 버튼에 맞지 않는다. `:has-text` 같은 확장 문법은 도구 버전에 따라 거부될 수 있으니, 그러면 `role=button[name=/넥슨 ID 로그인/]` 형태를 쓴다(둘 이상 일치하면 strict mode 오류로 실패하므로 정확히 1개가 보장된다). 사용자가 로그인 버튼까지 직접 눌렀다고 알리면 제출하지 않고 결과만 확인한다.
6. CAPTCHA·2단계 인증·QR 로그인 등 추가 절차가 필요하면 사용자가 브라우저에서 직접 완료하도록 요청하고 완료를 기다린다. 인증번호·OTP·보안 코드를 채팅으로 받아 대신 입력하지 않는다.
7. 로그인 성공은 계정별 페이지 상태로 확인하고 같은 세션에서 미완료 단계를 이어간다. 로그인 실패 여부는 `document.body.innerText` 평가로 안내·오류 문구를 읽어 판단한다(입력값은 `innerText`에 포함되지 않는다). 실패 메시지가 나오면 같은 입력으로 반복 제출하지 않는다(계정 잠금 방지). 실패 사실을 알리고 사용자가 직접 다시 입력하도록 요청하며, 다시 입력한 뒤의 제출도 한 번만 시도한다. 계정 잠금·보호조치·비정상 로그인 안내가 나오면 즉시 멈추고 사용자에게 알린다.
8. 사용자가 입력하지 못하거나 응답하지 않아 로그인을 끝낼 수 없으면 `조회 미확정/로그인 필요`로 기록하고, 인증이 필요 없는 확인만 계속한다.
9. **로그인 뒤 정리.** 로그인이 끝난(또는 중단된) 뒤, 이번 로그인 창 동안 도구가 자동 저장한 파일(`page-*.yml`, 스크린샷 png 등. 보통 `.playwright-mcp/` 아래이며 정확한 위치는 응답이 링크하는 경로를 따른다)만 이름을 지정해서 확인한다. 폴더째 삭제하거나 이전 파일을 건드리지 않고, `console-*.log`는 열지 않는다. 스냅샷 yml에 입력값이 남았는지는 값을 출력하지 않고 개수로만 확인한다. 개수는 PowerShell에서 `@(Select-String -LiteralPath <파일> -Pattern 'textbox .*\]:\s*\S').Count`, 다른 셸에서 `grep -cE 'textbox .*\]:[[:space:]]*[^[:space:]]' <파일>`로 센다. 결과가 0이 아니면 입력란 줄 뒤에 값이 남은 것이다. 값이 남았거나 내용을 확인할 수 없는 파일(로그인 창에서 찍힌 스크린샷 png 등)은 사용자에게 알린 뒤 삭제한다.

## 이벤트 코인형 미니게임

- 참참참·승부차기처럼 이벤트 안의 미니게임을 완료해야 보상이 확정되는 경우도 보상 수령 작업에 포함한다. 현황을 조회한 뒤 보유 코인, 회차별 비용, 보상 단계와 확률, 마지막 시도의 효과, 초기화 조건, 코인 만료 시점을 최신 공식 안내에서 확인한다.
- 사용자가 이벤트 보상을 받아 달라고 하거나 미니게임을 진행하라고 하면, 이미 획득한 무료 이벤트 코인으로 진행 가능한 시도까지 마친다. 결과가 무작위라는 이유만으로 무료 이벤트 시도를 남겨두지 않는다. 선택 가능한 보상이나 방식이 있으면 공식 확률·보상표와 최신 공개 시세를 찾아 기대 가치와 보장 하한을 비교한다. 정확한 확률·시세를 확인하지 못하면 그 한계를 알리고 하한이 높고 변동성이 낮은 보상을 우선한다. 결과가 자동으로 무작위 결정되고 선택지가 없는 미니게임이면 결과를 바꾸려는 조작을 하지 말고 이벤트 버튼으로 진행한다.
- 코인을 쓰기 전에 마지막 시도로 회차가 끝나는지, 완료하면 잔여 코인이 사라지는지, 초기화가 이미 쓴 코인과 진행을 없애는지 확인한다. 사용자가 이벤트 보상 수령이나 미니게임 진행을 요청했다면 보상을 확정하는 마지막 시도까지 실행하고, 지급 완료 메시지 또는 완료 상태를 확인한다. 이미 진행한 회차를 임의로 초기화하지 않는다.
- 현재 보유한 무료 이벤트 코인만으로 완주할 수 없다면 그 코인으로 가능한 단계까지 진행하고 멈춘다. 공식경기(친선 제외 1vs1·2vs2)처럼 별도 게임 경기가 필요해도 직접 시작하거나 대신 플레이하지 않는다. 공식 안내로 모드·코인 획득 조건과 필요한 경기 수를 확인해 사용자가 해야 할 일을 안내한다. 슛마다 필요한 경기 수가 다르면 남은 슛별 코인 비용과 총 경기 분량을 계산한다. 사용자가 경기를 마친 뒤 돌아오면 `조회`로 참여 현황을 갱신하고 저장된 단계부터 이어간다. 코인을 사거나 FC·BP·넥슨캐시·게임 보관함 아이템·다른 재화를 대신 사용하지 않는다.
- 예: 8회 승부차기의 4·7번째 슛은 2코인씩 필요하고 현재 6코인뿐이라면 앞선 단계의 비용을 계산해 가능한 시도를 진행한 다음, 남은 슛과 재개에 필요한 코인을 정확히 보고한다. 8번째 슛이 즉시 회차를 끝내는 규칙이면 누르기 전에 그 규칙과 보상표를 다시 확인한다.

## 이벤트마다 조회 → 미션 → 수령 → 검증

1. **참여 현황을 먼저 새로고침한다.** `조회`, `조회하기`, 참여 현황 갱신을 누르고 비동기 로딩·알림·모달이 끝날 때까지 기다린다. 초기 비활성 보상 버튼만으로 조건 미달을 판단하지 않는다.
2. **화면과 DOM을 함께 읽는다.** 조회 버튼이나 미션이 이미지형이거나 접근성 이름이 비어 있으면 최신 화면과 DOM에서 실제 요소를 식별한다. 과거 selector는 현재 페이지에서 요소와 목적을 확인한 뒤 사용한다.
3. **잠금 조건을 채운다.** 퀴즈라면 질문과 모든 보기를 확보한 뒤 공식 이벤트 안내·공지·가이드부터 검색하고, 필요한 경우 공개 웹 자료로 사실을 교차 확인해 가장 근거 있는 답을 선택한다. 정답·참여 완료 메시지나 상태 변화를 확인한 뒤 현황을 다시 조회한다. `방문하기`는 버튼의 공식 목적지에 실제로 이동해 페이지가 열린 것을 확인하고, 이벤트로 돌아와 현황을 갱신해 방문 기록을 확인한다. 버튼을 누른 것만으로 미션 완료라 하지 않는다. 불확실한 퀴즈는 추측하지 말고 그 항목만 미완료로 남긴 뒤 다른 미션과 이벤트를 계속한다.
4. **조건이 충족된 보상을 수령한다.** 날짜·주차·월 탭, 지난 기간 중 수령 가능한 보상, 화면 아래 추가 보상도 확인한다. 조회가 정상 완료된 후 신규/복귀 대상 여부를 판단한다.
5. **지급을 확인한다.** 지급 완료 메시지 또는 수령 완료 상태를 읽는다. 클릭 성공만으로 수령을 보고하지 않는다. 결과가 불명확하면 최신 상태를 다시 읽고, 이미 수령됐을 가능성이 있으면 중복 클릭하지 않는다.
6. 이벤트별 결과를 `새로 수령`, `이미 수령`, `조건 미달/미션 미완료`, `기간 종료`, `조회 미확정/로그인 필요` 중 하나로 기록한다. 한 페이지의 오류를 반복 시도하지 말고 다른 페이지를 계속 확인한다.

## 웹상점·멤버십과 추가 구매

- 요청에 맞는 현재 웹상점의 플레이어스/구매 멤버십 및 현재·지난달/지난주 보상을 확인한다. 등급, 기간, 보유/수령 상태를 새로 확인한다.
- `보상 수령`만 요청했다면 포인트·마일리지·코인 교환이나 상품 구매를 하지 않는다. 사용자가 구매를 별도로 요청하면 잔액·단가·한도·기한을 확인하고 해당 요청 범위에서만 진행한다. FC·넥슨캐시 충전이나 다른 재화 소진은 별도 지시 없이는 하지 않는다.
- 웹 수령만으로 게임 보관함 지급·개봉까지 완료했다고 말하지 않는다. 지급 지연 안내가 있으면 그 지연을 보고하고, 게임 아이템 처리를 요청받은 경우 해당 스킬로 이어간다.

## 완료 보고

새로 수령한 핵심 보상, 이미 수령된 항목, 미완료 미션과 원인, 지급 지연 또는 UI 오류를 간단히 구분해 보고한다. **사용자 후속 행동**을 반드시 포함한다. 별도 경기가 필요하면 진행 현황, 필요한 공식 모드, 남은 경기 수와 코인 비용, 사용자가 경기 후 이벤트에서 `조회`하고 다시 이어갈 절차를 적는다. 추가 행동이 없으면 `없음`으로 적는다. 별도 기록은 사용자가 지정한 위치에 요청된 경우에만 남긴다.
